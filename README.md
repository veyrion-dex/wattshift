# WattShift

WattShift подбирает расписание работы приборов по 24 почасовым ценам, допустимым окнам запуска и суммарному лимиту мощности. Сравнение показывает переменные затраты обычного и подобранного плана, расход энергии, пик и почасовую нагрузку.

## Запуск

Откройте `index.html` в браузере. Держите рядом `style.css`, `engine.js` и `app.js`. Установка зависимостей, сервер и аккаунт для расчёта не нужны. Для предсказуемого сохранения данных при ограничениях браузера на локальные файлы можно запустить `python3 -m http.server 8000 --bind 127.0.0.1` из папки проекта и открыть `http://127.0.0.1:8000`.

## Возможности

| Функция | Проверяемый результат |
|---|---|
| Импорт почасового тарифа | CSV читается из файла или текста. Пропуски, дубликаты и неправильные цены распознаются. |
| Управление приборами | Пользователь добавляет, изменяет и удаляет приборы, задаёт мощность и допустимое время работы. |
| Аудит обычного плана | Расчёт базовой стоимости, пиковой нагрузки и часов превышения условного лимита. |
| Оптимизация | Поиск допустимого плана минимальной стоимости с учётом всех приборов, а не только самого дешёвого часа. |
| Сравнение | Стоимость и расход, график нагрузки, интервалы работы каждого прибора, почасовая таблица. |
| Экспорт | Готовое расписание сохраняется в CSV. Доступен шаблон тарифа. |
| Восстановление | При поддержке локального хранилища тариф, приборы и сохранённый лимит восстанавливаются после открытия с того же адреса. |

## Три сценария

1. **Демонстрация.** Откройте проект в чистом браузерном профиле. Появятся три прибора и сравнение 3,341 → 1,835 условной единицы при тех же 9,8 кВт·ч. На другом сохранённом наборе можно воспользоваться кнопкой «Загрузить пример».
2. **Свои данные.** Импортируйте `tariff-example.csv` или CSV в формате `hour,price`, отредактируйте приборы и лимит, рассчитайте расписание. Допустимы строки с часом `08` или `08:00`, цены с точностью до четырёх десятичных знаков, варианты CSV с запятой либо точкой с запятой. На ошибочном CSV прежний план остаётся доступным.
3. **Сравнение и передача.** Откройте почасовую таблицу, сопоставьте два плана и скачайте итоговый CSV. Измените лимит, повторите расчёт и сравните результаты.

## Как считает

День состоит из 24 часовых интервалов. Прибор работает непрерывно с постоянной мощностью. Переменные затраты по каждому часу равны мощности в кВт, умноженной на цену за кВт·ч. Ограничение мощности проверяется отдельно в каждом часе. Поиск с отсечениями перебирает допустимые интервалы работы, при этом расчёт минимальной стоимости ведётся в целых единицах заданной точности. При достижении лимита поиска интерфейс отдельно отмечает, доказана ли оптимальность, и сохраняет лучшее найденное допустимое решение.

Модель поддерживает 1–8 приборов, один календарный день без перехода на летнее или зимнее время и цены от −1000 до 1000 в одной валюте. Приложение не получает тарифы автоматически, не переключает приборы и не учитывает фиксированные сборы, базовую нагрузку и переменную мощность. Лимит задаётся для перечисленных приборов в рамках расчёта. Демонстрационные тарифы и параметры вымышлены.

## Почему эта задача

- В мониторинге розничных рынков за 2026 год ACER связывает потенциал переноса потребления с типом договора, ценами и возможностью сдвинуть нагрузку. [Отчёт ACER](https://www.acer.europa.eu/monitoring/energy-retail-2026)
- В октябре 2026 года британский регулятор Ofgem открыл консультацию о методике расчёта ценовых ограничений для тарифов, зависящих от времени потребления. [Документ Ofgem](https://www.ofgem.gov.uk/call-for-input/energy-price-cap-updating-time-use-methodology)

Оба источника указывают на актуальность гибкого потребления. Влияние инструмента на поведение пользователей ещё требует наблюдения на реальных тарифах.

## Проверка

Тесты запускаются на Node.js 22+.

```bash
node --test engine.test.cjs app.test.cjs
```

Проверяются парсинг, расчёт с отрицательными ценами, конфликты мощности, исчерпание поиска, CSV и 80 сравнений с независимым полным перебором. Тесты интерфейсной логики используют имитацию DOM для демонстрации, импорта, редактирования, повторного открытия и экспорта. Для проверки реального рендера откройте приложение на ширинах 390, 768 и 1440 px, пройдите три сценария, проверьте консоль и прохождение основного маршрута с клавиатуры.
